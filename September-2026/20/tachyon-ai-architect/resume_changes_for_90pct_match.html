A silent failure, caught and fixed — and the lesson is the point

Status: resolved and verified. One of the eighteen intended changes did not apply on the first run and nobody was told, because nothing went wrong in a way a computer would notice. It has since been corrected, re-applied, and confirmed present in the database. The résumé you are looking at now carries all eighteen. This section stays on the page anyway, because the reason it happened is a trap that will happen again to somebody unless it is written down.

What went wrong

db/seats/tachyon-ai-architect.sql contains fourteen UPDATE statements. On the first run, thirteen of them changed a row and one changed nothing at all — and it did so without any error message, without a warning, and without failing the transaction.

The statement was the one meant to add “4 Reusable Archetypes” to the Decision-Intelligence Platforms skills label. Its WHERE clause named the key skills-tls-decision-intelligence-platforms-e. The real key in the database is skills-tls-decision-intelligence-platforms-event.

Where the truncation came from. The key was transcribed from a listing that had been cut off at 44 characters. The full key is longer than that, so the last four characters — vent — were simply not on the screen when the statement was written. Nothing looked wrong: a key ending in -e is a perfectly plausible key, and it was sitting in a file full of other keys that were all correct.

⚠ The trap, stated so it is hard to forget

In SQL, an UPDATE that matches no rows is a SUCCESS. It is not an error. It does not warn. It does not roll anything back. It reports that it updated zero rows and the script carries on to the next statement, and the transaction commits happily at the end.

So the number of statements you wrote is never evidence that the edits landed. Fourteen UPDATE statements ran, fourteen succeeded, and thirteen changes existed. A script that runs clean tells you the syntax was valid. It tells you nothing whatsoever about whether it found the rows you meant.

Only a diff against the database is evidence. That is what caught this one: the counts on this page are built by joining the master document against the seat document and asking the database which rows actually differ, and that query returned seventeen when eighteen were expected. The SQL run itself gave no hint at all. Had the page's counts been copied from the script instead of measured from the data, this would have shipped and nobody would have known.

Why this belongs with the repo's other measurement traps

CLAUDE.md keeps a list of occasions where a tool gave a confident, false answer that was acted on before anyone checked — grep -c counting lines instead of occurrences across minified files, a naive word counter treating an em-dash as a word and causing four good bullets to be trimmed, a regex matching hot-spot during a search for Fargate Spot, and one memorable case where dumping a single source produced a confident and wrong conclusion about what “the” source contained.

This is the same shape and deserves the same entry: the count of statements written is not a measurement of the changes made. Check the measurement before trusting the measurement.

What it looks like now

The key in the SQL file was corrected to ...-platforms-event, the statement was re-run, and the label now reads “Decision-Intelligence Platforms (Event-Sourced + Graph + AI, 4 Reusable Archetypes)” on the seat while the master still reads without the archetypes. Its before-and-after sits with the other Technology Leadership & Strategy change further up this page. score.json has been corrected to match, and now records 18 blocks — 14 edited plus 4 new — alongside 2 ordering operations, together with a note describing this failure and how it was found.

One thing worth saying plainly: nothing false was ever on the résumé because of this. The failure mode was an improvement going missing, not a fabrication going in. That is the better direction for a bug of this kind to fail in, but it is still a bug, and the only reason it is not still there is that the counts were measured rather than assumed.
