Tachyon Technologies: topics to learn

The topics to learn for the AI Architect interview, drawn from the job description and the gaps in Tech score gaps and Tech mismatch. A list only: he prepares on his own (his words, 30 Sep 2026).

Start with 1, 4 and 22. Tachyon is a consultancy whose customers run Azure, Salesforce, SAP and ServiceNow, and the role runs architecture workshops with them.

A. New to you (the gaps this job names)
  1. Azure AI services: Azure OpenAI, Azure AI Foundry and Azure AI Search, and how they compare with Amazon Web Services (AWS).
  2. AWS Bedrock and Google Vertex AI / Gemini: managed model hosting, and when to pick it over self-hosting.
  3. Multi-cloud architecture: what really changes between Azure, AWS and Google Cloud Platform (GCP): identity, networking, managed AI.
  4. Enterprise platform integrations: Salesforce, SAP and ServiceNow application programming interfaces (APIs) and connectors, and how AI plugs into them (events, APIs, middleware such as MuleSoft).
  5. Tool / function calling: how models call tools, designing tool schemas, and handling errors.
  6. The other agent frameworks: Semantic Kernel, AutoGen and CrewAI, and what each is good at compared with LangGraph.
  7. MCP (Model Context Protocol): servers, clients, tools versus resources, and security.
  8. Dedicated vector databases: Pinecone, Weaviate, pgvector and Azure AI Search vectors: choosing one, index types, hybrid search.
  9. Kubernetes for AI workloads: deployments, autoscaling and graphics processing units (GPUs), compared with Amazon ECS (Elastic Container Service) Fargate.
  10. Infrastructure as Code beyond Terraform: Bicep and CloudFormation basics.
B. You have done this; make it interview-ready
  1. Retrieval-augmented generation (RAG) in depth: chunking, embeddings, re-ranking, grounding, citation checks.
  2. AI evaluation: grounding, accuracy, hallucination rate, golden sets, a large language model (LLM) as judge, offline versus online evaluation.
  3. AI observability: tracing (LangSmith, OpenTelemetry), latency and cost monitoring, drift.
  4. Guardrails and Responsible AI: input and output filtering, handling personally identifiable information (PII), defending against prompt injection, human review.
  5. Choosing models: cost, latency and quality trade-offs; routing between small and large models; self-hosted versus an API.
  6. Identity and access for AI systems: per-user permissions on retrieval, tenant isolation.
  7. Event-driven architecture patterns: streams versus queues, event sourcing, sagas.
  8. Enterprise integration patterns: scatter-gather, API gateways, versioning.
C. Your own stories, told architect-to-customer
  1. The killer-query platform end to end, as one three-minute story: the business problem, then the architecture, then production.
  2. The LangGraph multi-agent orchestrator: why deterministic, and how the parallel finder agents and the barrier work.
  3. Self-hosted LLMs inside a private cloud: why, and the trade-offs.
  4. Running an architecture workshop or discovery session with a client (Tachyon is a services firm).
  5. Reference architectures and reusable components: your four query archetypes as the example.
