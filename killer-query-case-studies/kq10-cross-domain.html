Case study · ML system design · Healthcare

When a patient's payments, adherence, and support all break down at once — what did the platform do next?

For a chronic-care platform covering 80+ conditions, I designed the cross-domain interaction query — the architecture's hardest proof, that decision traces compound across finance, adherence, and operations — and took it to production. It is answered by a deterministic multi-agent orchestrator — the code owns the joins, the intersection, and the statistics; a language model is allowed only to narrate numbers the code already computed, and only after every gate has passed. The same discipline applies anywhere weak signals from separate systems must be joined without inventing a story: risk scoring, trust-and-safety escalation, incident correlation.

01 The problem

Three systems fail at once — and the easy query lies

The platform's defining bet is that decision traces compound across domains: a refund exception, a collapse in early adherence, and an escalated complaint are three different systems' signals, and the interesting patients are the ones where all three go wrong in the same window. This query is the strongest single argument for the whole architecture — and, precisely because it joins three domains, the one most prone to producing misleading numbers. Done naively it fails four ways at once:

  • Coincidence dressed as a pattern — three events that merely happened within a year are not a cross-domain episode. Without a window rule you manufacture cohorts out of unrelated timelines.
  • Confounding by design — patients whose finances, adherence, and support all break down are sicker and more complex than average, so a raw outcome comparison is confounded before it starts.
  • Cross-domain identity collisions — joining finance, adherence, and operations records on a loose key silently mixes the wrong people, and across tenants that is a reportable incident.
  • Blame framing — "what happened to the patients who complained and missed doses" reads as a service-quality scorecard the moment the table exists, even though this is a help-seeking population by construction.

The design treats each as a first-class requirement with a named control — and answers the whole thing with a deterministic multi-agent orchestrator, not a prompt.

02 The architecture

Two stages: a snapshot cohort screen, then a per-patient chain walk

This query is the capstone of a four-archetype system, and it composes two of them. Stage A is a cohort screen — a nightly, snapshot-only pass that finds the patients whose finance, adherence, and ops signals all broke inside one 90-day window, using tenant-scoped analytical joins over frozen columnar files: no live graph, no per-patient traversal. Stage B is a per-patient drill-in — when a reviewer opens a single patient, the service delegates to a deterministic single-patient chain service with an explicit 90-day window. Stage A is pre-computed nightly; Stage B is on-demand only and never pre-walked.

The overlap-window predicate

Every qualifying patient must have all three events — the refund exception, the early-adherence failure, and the escalated complaint — inside a single 90-day window. Rows that fail the predicate are rejected outright; the pivot is never quietly stretched to force a match. The pivot, the window bounds, and the rule version are persisted on every row, so two runs of the same cohort are the same cohort — and a downstream query cannot silently produce a slightly different one.

The snapshot at the head of that pipeline is a frozen projection of the append-only event spine, not a live database read, so the whole nightly build is reproducible from history — the same corpus yields the same cohort. And because an upstream refund, adherence, or ops correction retriggers only the slices that depend on it — dependency-targeted, with a P95 correction-to-refresh under five minutes — a single late reversal refreshes in minutes rather than waiting for, or forcing, a full overnight recompute.

03 Hydration

Nine years of history, replayed into the spine

This query does not begin against an empty world. Roughly nine years of prior finance, adherence, and operations records were hydrated through the same append-only spine that now carries live events — a first-class, quarantine-first, proof-carrying pipeline, not a throwaway backfill. Five properties make that load trustworthy enough to build a cross-domain cohort on top of:

  • Event time is not ingestion time. Each legacy record keeps the real-world moment it happened, alongside the source's own observed-at time; only the received and written timestamps record when the system learned of it. Collapse event time into ingestion time and nine years of decisions would look as though they all happened on load day, voiding every as-of reconstruction — which is always ordered by an event's own time and source sequence, never by the order it happened to be written. The watermark policy differs in hydration mode — where a nine-year spread of "late" data is normal — from the small operational value used live.
  • Hydrating twice is a no-op. Content-addressed event IDs plus conditional writes make the load idempotent and resumable; re-running the pipeline over the same corpus yields an identical spine and an identical snapshot-manifest hash. That is an executable proof, not an assurance.
  • Nothing is silently coerced. Nine years means many legacy payload-schema versions; each gets an upconverter, and any row that cannot be mapped to a schema or to a tenant is quarantined and counted, never defaulted. A defaulted tenant would be a cross-tenant leak — the exact failure this query's identity discipline exists to prevent.
  • The same projection code runs for history and for live. History is replayed through the projection logic that serves the live stream; otherwise the hydrated graph would be a different product from the streaming one and every determinism guarantee would be theatre.
  • The load is proof-carrying. Zero-event-loss reconciliation against the source, per-tenant and per-class counts, as-of spot checks against known-good historical reports, and a golden replay over a historical slice gate the load before anything downstream is built. A fenced cutover then attaches the live stream with a proof of neither gap nor duplicate at the boundary.

The overlap-window predicate compares three domains at their true event times, so the whole cohort is only as sound as the timestamps underneath it. Hydration assigns four event-time fields per event class: the real-world moment and the source's observed-at time come from the record, while the received and written timestamps are pinned to a single load fence — never the load clock. As-of order sorts by event time then source sequence, so the arbitrary order in which nine years were written back is irrelevant; and an invariant asserts every historical event's real-world time falls strictly before the moment the system received it — the tripwire that catches an event time accidentally defaulted to ingestion time.

Collapse any one domain's event time into ingestion time and all three signals would appear to land on load day: the 90-day window would admit everyone or no one, and the cross-domain episode this query exists to find would dissolve into an artefact of the load.

What nine years buys this query is the cross-domain window itself. A refund exception, a collapse in early adherence, and an escalated complaint can only be judged to fall inside one 90-day pivot if finance, adherence, and operations events all coexist over the same historical span — at the same event-time resolution, under the same tenant scope. Stage A's nightly cohort screen and Stage B's per-patient chain walk are only as deep as the history behind them; without the hydrated span there is no cross-domain episode to find, and the overlap-window predicate would have almost nothing to admit or reject.

04 The orchestration

The orchestrator is a graph, not a prompt

Stage A is where the multi-agent machinery lives, and the discipline is the entire point: the orchestrator is a declared, deterministic LangGraph state graph. Its edges are fixed code; the only place a language model may appear is inside a single node body. Four orchestration primitives, expressed as graph structure:

  • Parallel blind finders — three finder agents (finance, adherence, ops) fan out from the start and run concurrently. Each is a narrow persona that never sees the others' results.
  • Barrier — a fan-in node runs once, after all three finders return, and intersects their patient-id sets through the overlap-window predicate. Nothing downstream starts until the intersection exists.
  • Pipeline drill-in — each matched patient's chain is built independently; patient two drills in while patient fifty is still being fetched.
  • Gated reduce — the matched-control comparison and clustered bootstrap run behind a balance gate; under-powered, the delta is suppressed, not degraded.
  • Synthesis with a feedback loop — one node composes the optional per-patient chain narrative, while the cohort delta itself is served as numbers, never a sentence; a conditional edge forms a real cycle where a hallucinated citation is caught by output validation and the node re-prompts once with the offending citation flagged, then suppresses the narrative.

This is the only query in the programme whose orchestrator is runnable code — a compiled state graph the in-VPC runtime serves directly, with typed contracts on every channel between nodes.

The state graph shows the wiring; the execution shows the discipline. The three finders run concurrently on the cheap tier, and the barrier does more than wait — it re-verifies every proposed patient id against the frozen snapshot and the overlap-window predicate before that id is allowed to count, which is why a finder that hallucinates a patient cannot smuggle one into the cohort. 05 The honesty gates

Two gates decide whether a number is allowed to exist

Before any cross-domain delta reaches a screen it passes two deterministic gates, in order. First a power gate: matched-pair N, effective-N, and CI-width must all clear their thresholds, or the cell returns descriptive facts only — cohort and matched counts with full denominators, and no causal-looking delta. Then a balance gate: every covariate's standardised mean difference (SMD) must sit under the gate and the sensitivity bounds must hold, or the delta is suppressed and only descriptive facts plus the failed-balance diagnostics are returned. The small-cohort rule here is a statistical-reliability floor, not merely a privacy N-floor — a confident number from a handful of unusually complex patients is exactly the failure this query would otherwise produce.

The histogram is labelled "observed follow-up decisions," never "recommended action," and every emitted surface carries observational, non-causal labels. Matching can only balance what is measured — unmeasured confounding is never ruled out — which is exactly why nothing here is ever presented as a causal claim or a service-quality score.

06 Guardrails

Every way this could mislead has a named control

07 The LLM boundary

The language model writes words, never numbers

This is the portfolio's sharpest case of knowing when not to use an LLM. The intersection, every per-patient chain, the balance gate, and every statistic are deterministic code. A language model appears only at the edges — cheap-tier finder agents proposing candidate patients per domain, and an optional synthesis narrator — never inside the numbers: a finder cannot smuggle in a patient, because the barrier re-verifies every proposed id against the frozen snapshot and the overlap-window predicate before it counts. The narrator, an optional Stage-D step, only puts words to a single patient's chain the code already assembled, and even it is off by default until the narrative-guardrail contract ships. When it is on, it runs behind three protections: a typed claim grammar that rejects any narrative whose citations are not grounded in the chain, a self-hosted Llama cascade so PHI never leaves the VPC, and a fail-quiet default so a model outage costs a sentence of prose, not a number, a gate, or a control.

The system uses the phrase "feedback loop" for two different machines, and keeps them apart. Loop A is deterministic data-plane re-derivation: a correction lands on the spine, a dependency index evicts the derived keys that depended on it, and just those are rebuilt — no model involved. Loop B is model-in-the-loop self-correction: a synthesis narrative cites a node that is not in the chain, a typed validator flags it, and the node re-prompts once with the offending citation flagged; if it still fails, the narrative is suppressed. Same word, different machines — one re-derives data with code, the other re-prompts a model behind a code gate, and both are bounded.

  • Routing is auditable code, not a hidden prompt: a pre-hoc classifier sends easy calls to the free 8B (with a structured-output, few-shot, self-consistency boost) and hard calls to 70B; a post-hoc confidence gate escalates the uncertain tail. Most traffic clears on the free 8B; only the tail the gate flags as uncertain escalates to 70B, and every routing decision is auditable code.
  • Self-hosted inference for PHI: the one narrative call runs on Llama 3.1 inside the VPC via the native Ollama API — no vendor SDK, no external egress — so patient data never leaves the cluster.
  • Governance as code, not prompt: the observational labels and neutrality rules ship as deterministic UI copy; there is no prompt to jailbreak, because the claims never pass through the model.
08 The RAG pipeline

Retrieval-augmented, and the retrieval is a governed query

When the optional synthesis narrator is on, it is the one place this system resembles retrieval-augmented generation — so it is worth being exact about what the retrieval actually is. It is not a vector search over documents. It is a governed query against the context graph: tenant-scoped, reconstructed as of the decision, and gated before a model ever sees it. Here "retrieve" means two joined structured reads — Stage A's cross-domain cohort screen, then a single patient's deterministic chain — and the model's only job is to say in one sentence what a single patient's retrieved chain already shows. The cohort screen itself is served as numbers — a histogram, an outcome delta, a confidence interval — never a sentence. A validator rejects the sentence if it says anything else.

Five stages, and a number never depends on any of them:

  • Retrieve. The query's own governed reads — the cohort screen and the per-patient chain drill-in — with the tenant filter inside the query, not applied after it.
  • Assemble. A typed, as-of context object: only fields that existed at the pivot, each carrying its provenance. Post-decision evidence never enters the context.
  • Generate. A pinned model version and a pinned system prompt at temperature 0, self-hosted in-VPC on the Llama cascade so PHI never leaves the network. The prompt forbids computing, re-ranking, or concluding.
  • Validate. Every citation must resolve to a real chain node and a structurally valid edge; a claim grammar decomposes each factual sentence into templates backed by cited fields and rejects anything it cannot decompose; a leakage guard rejects any post-decision value.
  • Serve or suppress. A failed validation re-prompts the synthesis node once with the offending citation flagged; if it fails again the narrative is suppressed with failure metadata. The cohort and the chain are served either way — the answer never depends on the model.

Three invariants hold across every response: no number is written by a language model — code computes, the model narrates; every generated sentence carries a citation that resolves, or it is not served; and hashes pin the inputs and the output so any narrative can be re-derived and audited. On the regulator and audit surfaces the structured cohort and chain are authoritative and the sentence is an optional appendix.

09 The stack

Boring infrastructure, deliberate framework choices

The analytical core is deliberately unexciting — columnar files and an embedded query engine, each doing one job. The orchestration and AI layer reuse the platform's LangGraph runtime and LangChain seam, with observability designed for PHI from the start.

Before the component tables, it helps to see when each part is touched and where the trust boundary sits. Three lanes carry the work. The request path is the only thing a clinician waits on: the API resolves the role, writes the audit entry, and reads a pre-computed cell from the cache — or, on a miss, from the columnar serving store. The nightly lane runs offline with nobody waiting — it exports the snapshot, builds the cohort, matches controls, computes the statistics, and rebuilds only the slices a correction touches. The one-time historical lane is the hydration that seeded the spine. Every lane runs inside the client VPC; only the clinician's browser, over TLS, sits outside the boundary — and the two heaviest components sit deliberately off the request path.

11 The review gauntlet

Ship-with-changes, then hardened into the platform that carries it

Before anything shipped, the design went through structured adversarial self-review under a Principal-AI-Engineer lens — and this query, the most exposed in the whole system, drew the most blood: twenty findings across correctness, statistics, governance, and operations, with an unambiguous "do not implement as written."

  1. Design review · round 1 Ship-with-changes — including an undefined overlap window, live-graph leakage into the nightly snapshot cohort screen, coarse outcome labels, an unsafe dependency on the patient-chain service, and a flat refusal of the idea that a raw delta on failed balance could ever be returned.
  2. Design revision · v2 The twenty query-local findings were absorbed directly into this design body: the overlap-window predicate that rejects rows, snapshot-only Stage A, the shared outcome labeller, balance-fail suppression, and the audited, need-to-know per-patient drill-in.
  3. Shared-platform components Its cross-cutting dependencies — the tenant wrapper, the outcome and bootstrap libraries, the correction backbone, and the deterministic patient-chain artifact — were promoted into shared platform components and have since landed, so every sibling query inherits the same fixes instead of reimplementing them; the query now binds to the shared versions. The one dependency still open is the narrative-guardrail contract, which remains unsigned, so the synthesis narrator ships off by default. The runnable orchestrator goes through the same hiring-CTO review loop documented in the precedent-search case study.

12 Delivered

What was delivered — and where it transfers

  • A production deployment — the cross-domain analytics service live on the platform's self-hosted, in-VPC stack, serving governed exec/ops dashboards and audited per-patient drill-ins. Shipped after executive sign-off on the design.
  • A complete design packet — the two-stage pipeline spec, the overlap-window predicate, the cross-domain identity key, the shared statistical contracts, API envelopes with full provenance pins, the RBAC/audit governance spec, and correction SLAs.
  • A runnable work sample — the multi-agent orchestrator as a LangGraph state graph, plus a demo that contrasts the two kinds of feedback loop, running deterministically offline in CI with zero API keys; the run prints a DETERMINISTIC / LLM / GATE banner per stage, the balance gate suppressing an under-powered cohort, and a fabricated citation being caught and corrected on retry.
  • A review audit trail — a twenty-finding adversarial design review, the query-local findings absorbed into v2 and the cross-cutting dependencies promoted into shared platform components every sibling inherits, and a prepared work-sample review as the next gate.

The pattern generalises well beyond healthcare: any system that must join weak signals from separate systems into one honest picture — finance, support, and operations for a risk score; telemetry, tickets, and deploys for incident correlation; the many streams behind a trust-and-safety escalation. If you need to orchestrate agents deterministically, join across domains without inventing a story, and keep the language model away from the arithmetic — this is the discipline I bring.
